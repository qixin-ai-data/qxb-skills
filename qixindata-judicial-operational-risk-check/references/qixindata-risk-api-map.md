## 接口去重与最小化调用建议

目标是“够用就好”，不要为了信息完整感而把功能重叠的接口全部调用。

### 第一层：默认最小组合

| 场景 | 首选接口 | 说明 |
| --- | --- | --- |
| 基础画像与尽调底稿 | `47.51` | 优先承接基础档案、集团、历史沿革、资质、融资等信息 |
| 风险总览 | `55.29` | 优先承接经营、税务、司法、处罚、异常等风险概览 |
| 总体评级 | `72.51` | 作为综合风险等级主依据 |

### 第二层：只在需要时补充

| 接口 | 何时补充 | 不必补充的情况 |
| --- | --- | --- |
| `1.41` | `47.51` 缺基础照面信息或关键信息冲突 | `47.51` 已足够支撑基本情况 |
| `30.4` | 需要补充信用质量、实力平衡 | 只需风险结论，不需信用视角 |
| `79.23` | 司法风险较重，需要解释司法强度 | 司法命中少且 `55.29` 已足够说明 |
| `27.59` | 需要补充风险数量摘要 | `55.29` 摘要已足够清楚 |
| `1.47` / `24.28` | 变更风险需要具体前后变化 | `47.51` 历史沿革已足够 |
| 处罚/涉诉明细接口 | 需要案号、机关、金额、时间等代表性细节 | 聚合摘要已足够支撑结论 |
| `55.5` / `55.3` / `33.9` / `59.5` | 关联关系不清或需识别高风险关联主体 | `47.51` 已能识别核心集团与子公司 |

### 第三层：能复用就复用

对同类信息，优先按下列顺序复用：

| 信息类型 | 优先来源 | 次选来源 |
| --- | --- | --- |
| 基础工商信息 | `47.51` | `1.41` |
| 风险模块命中概览 | `55.29` | `27.59` |
| 经营/合规/涉诉细节 | 对应聚合块 | 对应明细接口 |
| 集团/子公司/投资关系 | `47.51` | `55.5`、`55.3`、`59.5`、`33.9` |

不要把“次选来源”当成默认来源。

## 模块细节字段提示

生成全景风险尽调报告时，不要只写“是否命中”，各模块应尽量带出以下关键字段。

| 模块 | 建议细节字段 |
| --- | --- |
| 经营风险 | 时间、风险类型、机关/来源、结果、金额/对象、当前状态 |
| 变更风险 | 变更项目、变更日期、变更前、变更后、变更频次 |
| 合规风险 | 标签/处罚类型、时间、机关/来源、处罚结果、归因依据 |
| 涉诉风险 | 案号、身份、案由、时间、法院/机关、金额/结果 |
| 关联风险 | 关联公司、关联关系、核心风险类型、代表性事件、来源 |

如果原始接口字段很多，不要全量搬运；优先保留最能支撑判断的字段。

## 关联风险补齐规则

### 1. 关联主体扩池范围

默认只扩以下 4 类主体，不做无限外延：

| 类别 | 主来源 | 补充来源 | 纳入条件 |
| --- | --- | --- | --- |
| 实控人控制企业 | `55.5` | `47.51` | 存在明确控制、持股或实际控制关系 |
| 疑似关联方 | `33.9` | `47.51` | 接口已识别为疑似关联且关系理由清晰 |
| 高管对外任职/投资企业 | `59.5` | `55.5`、`55.3` | 主要人员对外任职、投资，且持股或控制关系明显 |
| 母公司/子公司/兄弟公司 | `47.51` | `55.5`、`55.3` | 存在集团、投资、母子公司或同一控制链证据 |

停止条件如下：

- 不追查“关联方的关联方”
- 不因单一姓名重合就扩池
- 不因普通历史任职且无控制关系就扩池
- 不因弱疑似关系或缺乏关系说明就扩池
- 默认排除吊销、已注销、已清算等非存续主体

### 2. 关联风险补查范围

对扩池后的关联主体，不需要完整复刻整份企业报告，只补查高价值风险信号。

优先补查以下风险：

- 重大被执行、失信被执行、限制高消费等司法强风险
- 重大税收违法、欠税、非正常户等税务强风险
- 严重违法、重复行政处罚、重大环保处罚等合规强风险
- 破产、清算、注销异常、重大资产负担等经营存续风险

默认优先使用聚合接口先看是否命中，再决定是否补明细。
如果聚合结果已足以支持结论，不强制继续拉取全部明细接口。

### 3. 风险分类口径

关联风险结论只允许归入以下两类：

| 类型 | 定义 | 典型条件 | 表述要求 |
| --- | --- | --- | --- |
| 直接关联风险 | 目标企业与风险主体之间存在强关系，且风险可能直接影响合作判断 | 控制关系、集团关系、关键人员重合、共同经营要素等强信号明显 | 可以写入关联风险重点提示 |
| 强传导风险 | 风险主体不一定是目标企业本体，但与目标企业存在明确控制链或核心经营关联，重大风险有外溢可能 | 实控人控制企业、核心集团企业、高管控制企业命中高严重度风险 | 必须写明“传导”或“提示”，不能写成目标企业已直接命中 |

以下情况不升级为重点关联风险：

- 普通疑似关联方仅命中一般异常或零散轻微处罚
- 高管外部普通任职企业存在轻微风险，但无控制关系
- 无法证明关联强度或传导链路

### 4. 关联风险输出建议

关联风险章节建议稳定输出以下内容：

- `核心关联方清单`：只保留与目标企业关系最强的主体
- `高风险关联方`：只列入命中直接关联风险或强传导风险的主体
- `关联关系说明`：只说明该主体为存续公司，以及它与目标企业的关系类型

### 5. 证据与谨慎表述

- 关联主体命中的风险，应尽量保留原始风险类型、时间和来源
- 需要在 `source_refs.note` 标注 `直接关联风险` 或 `强传导风险`
- 如果只有关联关系，没有明确风险命中，不要硬写成风险
- 如果只有风险命中，但关系强度不足，也不要升级成重点结论
- 最终面向用户的正文里，不展开剔除原因、主体状态字段或传导依据长说明，只保留“存续公司”与“关联关系”两个识别结果

## 二级风险标签抽取规则

只有在当前报告块里没有直连字段时，才启用这些规则。

| 二级标签 | 首选证据 | 备用证据 | 填写原则 |
| --- | --- | --- | --- |
| 安全疏忽 | 行政处罚、环保处罚、产品投诉 | 新闻负面标签 | 无证据填 `无` |
| 非法集资 | 严重违法、行政处罚 | 新闻关键词、外部黑名单 | 仅间接证据时标记为归因抽取 |
| 非法经营 | 经营异常、严重违法、行政处罚 | 外部黑名单、新闻 | 无证据填 `无` |
| 商业贿赂 | 行贿违法、行政处罚 | 新闻关键词 | 区分直接命中与归因线索 |
| 围标串标 | 招投标记录、行政处罚 | 新闻关键词 | 间接证据仅作为风险提示 |
| 市场垄断 | 行政处罚 | 新闻关键词 | 无监管认定时不要过度表述 |
| 不正当竞争 | 行政处罚 | 产品投诉、新闻 | 无证据填 `无` |
| 违规推广 | 行政处罚 | 新闻、产品投诉 | 无证据填 `无` |
| 雇佣童工 | 行政处罚 | 新闻关键词 | 无证据填 `无` |
| 信息泄露 | 行政处罚 | 新闻关键词 | 无证据填 `无` |
| 质量问题 | 产品召回、产品投诉 | 食品安全、质量监督抽查、新闻 | 优先采用产品类直接记录 |

## 缺口与回退规则

- 目录中没有直连字段，也没有足够一级证据时，填 `无`
- 接口调用失败、当前 route ref 无法确认、或数据未成功拉取时，填 `未获取`
- 不要凭空编造命中数量、金额或等级
- 不要因为存在少量正向信息就弱化实质性风险
