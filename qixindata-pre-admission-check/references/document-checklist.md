# Comparison Checklist

在需要做字段比对、通用资料核对或按客户内部清单做定制化比对时读取本文件。

## Comparison Modes

先判断当前是哪一种：

- `profile-only`
含义：客户没给待比对字段，只看企业照面信息。
输出重点：主体核验结论 + 企业照面信息。

- `generic-compare`
含义：客户给了部分字段，想和库内信息对一下。
输出重点：只比对客户给的字段，不额外生成完整缺件清单。

- `custom-compare`
含义：客户给了内部清单、特殊规则或必须核验项。
输出重点：按客户清单顺序逐项核验，并明确不一致、待补、待人工核项。

## Generic Comparable Fields

如果客户没有给内部清单，但已经给了部分资料，优先支持比对这些常见字段：

- 企业名称
- 统一社会信用代码
- 注册号
- 法定代表人或负责人
- 注册地址或联系地址
- 电话
- 邮箱
- 官网或备案域名
- 分支名称与总公司归属
- 许可证/资质名称
- 许可证编号
- 有效期

## Result Labels

字段比对结果统一用以下几档：

- `一致`
定义：用户提供值和库内核心字段一致。

- `基本一致`
定义：存在格式差异、简称差异、旧地址/新地址、历史名称/现名称等可解释偏差，但整体可判为同一主体或同一信息链。

- `不一致`
定义：用户提供值与库内关键信息明显冲突，且当前没有足够证据解释。

- `用户未提供，无法比对`
定义：该字段用户没有给值，本轮不做判断。

- `库内当前未见，待人工核`
定义：公开库当前未见足够信息支撑判断，不能直接下否定结论。

## How To Handle Missing Information

- 客户没有提供某字段时，不要主动写成“缺件”。
- 只有在客户明确要求核这个字段，或内部清单里要求核这个字段时，才把它放进待补或待核表。
- 当客户只是想“先看主体对不对”时，停在企业照面信息，不扩展到资料齐全性。

## Custom Checklist Input

如果客户想定制化比对，引导其按这个格式提供：

```text
请按贵司自己的要求，把要核验的字段或材料直接发给我，例如：

- 统一社会信用代码
- 法定代表人
- 注册地址
- 联系电话
- 官网
- ICP/备案域名
- 某项许可证名称和编号

如果有内部规则，也请一起说明，例如：
- 地址必须和营业执照一致
- 必须核分支归属
- 必须核许可证是否在有效期内
```

## Closing Guidance

默认结尾补一句：

- 当前如果只做了企业照面核验：
  - “如果您方便，后续也可以把营业执照、法人、地址、联系人、官网或许可证信息发给我，我可以继续帮您逐项核对。”

- 当前如果只做了通用比对：
  - “如果您希望按贵司自己的准入清单继续核验，也欢迎把清单或规则发给我，我可以按你们的要求继续做定制化比对。”
