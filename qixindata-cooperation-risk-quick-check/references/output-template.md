# 输出模板

成功完成速查时，按以下四段输出，不增不减。

```markdown
# 合作前风险速查

## 1. 速查结论
- 结论：未见明显阻断风险，可进入下一步评审 / 存在待核风险，建议人工复核/补充尽调 / 存在明显阻断风险，建议暂缓合作
- 判断说明：用 1 到 2 句话说明主体是否已确认、是否命中明显风险信号、为什么进入当前结论。

## 2. 主体确认与基本信息
- 主体确认：已确认 / 存在歧义 / 未找到可靠信息
- 主体说明：说明是精确命中、统一社会信用代码交叉确认，还是存在多个候选主体。
- 企业名称：
- 统一社会信用代码：
- 法定代表人：
- 登记状态：
- 成立日期：
- 经营范围：

## 3. 风险信号摘要
- 诉讼/司法信号：命中相关记录 / 未命中相关记录 / 未找到可靠信息 / 当前接口未覆盖 / 本次接口调用失败
- 行政处罚：命中相关记录 / 未命中相关记录 / 未找到可靠信息 / 当前接口未覆盖 / 本次接口调用失败
- 经营异常：命中相关记录 / 未命中相关记录 / 未找到可靠信息 / 当前接口未覆盖 / 本次接口调用失败
- 失信被执行：命中相关记录 / 未命中相关记录 / 未找到可靠信息 / 当前接口未覆盖 / 本次接口调用失败
- 被执行：命中相关记录 / 未命中相关记录 / 未找到可靠信息 / 当前接口未覆盖 / 本次接口调用失败
- 税务风险：命中相关记录 / 未命中相关记录 / 未找到可靠信息 / 当前接口未覆盖 / 本次接口调用失败
- 备注：只写会影响判断的 1 到 3 条重点事实，不写长段解释。

## 4. 证据来源与下一步建议
| 证据摘要 | 来源 |
| --- | --- |
| 企业主体确认结果 | `qxb_op_enterprise_resolve` |
| 风险扫描总览与命中模块 | `cn_cooperation_risk_scan` |
| 如有补查，再写补查接口及事实 | `具体接口名` |

- 下一步建议：写成动作句，例如“建议进入法务复核”“建议补充专项诉讼核查”“建议暂缓发起合作审批”。
```

## 失败模板

如果关键接口失败导致速查未完成，改用以下模板，不要套用成功模板：

```markdown
# 合作前风险速查

## 1. 速查状态
- 状态：本次速查未完成
- 失败原因：直接写接口返回的核心错误，例如“QXB API 凭证或授权校验失败，请检查 appkey、secret_key、IP 白名单和接口授权状态”。

## 2. 失败位置
- 失败接口：`qxb_op_enterprise_resolve` / `cn_cooperation_risk_scan` / `qxb_op_result_query` / `具体补查接口`
- 失败阶段：主体确认 / 主速查 / 结果钻取 / 必要补查
- 是否已产生可用风险结论：否

## 3. 本次未完成项
- 主体确认：未完成 / 已完成
- 风险速查：未完成 / 部分完成 / 已完成但关键证据不足
- 备注：只写与失败直接相关的阻断信息，不写公开来源补充判断。

## 4. 下一步建议
| 项目 | 建议 |
| --- | --- |
| 接口处理 | 优先检查凭证、授权、白名单、接口可用性和参数正确性 |
| 业务判断 | 在接口恢复前，不输出合作放行、待核或暂缓合作结论 |

- 补充说明：不要使用公开来源替代启信 MCP 结果。
```

## 模板使用规则

- 尽量保持每段简短。
- 如果字段缺失，明确写 `未找到可靠信息`。
- 如果主体未确认，在第 1 段和第 2 段都要写清楚，不要隐藏。
- 第 3 段只保留与合作决策有关的风险项，不要扩展成完整尽调清单。
- 如果接口失败，必须切换到失败模板。
- 失败模板中不要输出任何公开来源补充结论。
