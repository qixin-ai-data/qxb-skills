# 规则覆盖说明

这个 skill 基于 `启信慧眼-风险预警-启信慧眼默认规则(国内)` 工作簿整理，只保留当前能够被 QXBMCP 直接映射的规则族。

## 默认核心范围中保留的规则族

默认每日流程覆盖以下部分：

- `基本信息`
  以 `cn_company_change_records` 作为主要增量来源，覆盖名称、类型、注册资本、地址、经营范围、法定代表人、股东股权、主要人员、分支机构、期限等变化。
- `经营风险`
  优先使用 `cn_cooperation_risk_scan`，只有需要核实时再向具体细分接口下钻。
- `司法风险`
  优先使用 `cn_cooperation_risk_scan`，只有需要核实时再向立案、开庭、法院公告、执行、失信、司法拍卖、破产等细分接口下钻。
- `企业舆情`
  使用 `cn_company_news`。

## 作为可选扩展保留的规则族

这些规则族能够直接映射，但会增加调用成本，因此改为按需启用：

- `关联方风险`
  使用 `cn_company_actual_controllers`、`cn_company_beneficial_owners`、`cn_company_suspected_related_parties`、`cn_company_group_members` 发现候选关联实体，再对短名单复用 `cn_cooperation_risk_scan`。
- `供应链风险`
  使用 `cn_company_supply_chain`，必要时补 `cn_company_suppliers` 和 `cn_company_customers`，再对短名单对手方复用 `cn_cooperation_risk_scan`。
- `经营信息`
  只在用户明确要求更宽的经营与知识产权覆盖时，才启用对应扩展接口。

## 已删除的规则族

以下规则族不进入执行范围，因为当前国内版 QXBMCP 没有干净的直接映射，或者工作簿逻辑依赖的是未暴露的规则引擎能力，而不是可直接调用的接口结果：

- `供应链风险 > 自然灾害`
- `供应链风险 > 社会异常事件`
- `自主上报风险`
- 所有依赖内部评分变化、内部事件标签、或未暴露信号计算逻辑的规则
- 所有只定义内部阈值、但当前没有对应 QXBMCP 可检索事件源的工作簿行

## 覆盖判断原则

统一按以下顺序判断：

1. 如果存在直接的 QXBMCP 事件源或聚合报告分块，就保留。
2. 在保留的前提下，优先选择所需接口数量最少的实现方式。
3. 日常监控优先使用聚合报告，细分接口仅用于下钻核实。
4. 无法直接覆盖的规则直接删除，不用弱代理逻辑硬凑。
