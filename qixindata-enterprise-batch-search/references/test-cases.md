## Purpose

本文件用于做跨模型回归测试。目标不是要求不同模型输出逐字一致，而是要求它们：

- 接收同一类真实客户输入
- 走同一条入口路线
- 使用同一组筛选口径
- 输出同一套结构化结果

## Test Case 1: 开发区内科技类小额企业初筛

### 真实客户输入

```text
帮我找一批哈尔滨经济技术开发区里的科技类企业，优先看还在经营的，注册资本别太大，先控制在 500 万以内。先给我一版可跟进的企业名单，最好带上企业 ID、法人、成立时间和地址。
```

### 适用原因

这个输入贴近真实客户开发或供应商初筛场景，特点是：

- 语言自然，不会像接口参数说明
- 同时包含范围、行业倾向、经营状态、资本区间、输出字段
- 会触发 skill 的“开发区企业 + 二次核验”路线

### 期望的内部解析结果

```json
{
  "entry_route": "zone",
  "location_anchor": "哈尔滨经济技术开发区",
  "industry_keywords": ["科技", "软件", "技术服务", "系统集成", "物联网"],
  "status_required": ["存续", "在业"],
  "registered_capital_min": null,
  "registered_capital_max": 500,
  "start_date_range": null,
  "tag_filters": [],
  "entity_nature_filters": [],
  "scale_filters": [],
  "scope_keywords": ["软件开发", "技术开发", "技术服务", "系统集成", "信息技术服务", "物联网"],
  "page_size": 100
}
```

### 期望使用的接口路线

1. `cn_development_zone_companies`
2. `cn_company_registration_face`
3. 如需增强，可选 `cn_company_concept_labels`

### 不应发生的情况

- 不应把请求改写成“全国企业搜索”
- 不应忽略“还在经营”和“500 万以内”两个条件
- 不应只凭企业名称含“科技”就直接判定为强匹配
- 不应输出一段长篇分析替代表格

### 期望输出结构

```markdown
## 检索条件
- 入口路线：开发区企业
- 地理范围：哈尔滨经济技术开发区
- 本次已执行的筛选条件包括：经营状态为存续/在业、注册资本不超过 500 万、科技相关经营范围初筛
- 以下条件当前仅做近似筛选：科技相关主要依据经营范围关键词

## 结果概览
- 候选企业总数：
- 本次展示数量：
- 已完成二次核验数量：
- 说明：以下结果仅代表当前入口下前 N 条样例，不代表全量

## 企业列表
| 序号 | 企业名称 | EID | 统一社会信用代码 | 法定代表人 | 注册资本 | 成立日期 | 经营状态 | 匹配等级 | 匹配说明 | 核验备注 |

## 后续建议
- ...
- ...
- ...
```

### 期望输出字段解释

- `企业名称`：标准企业名称
- `EID`：来自 `cn_company_registration_face.id`
- `统一社会信用代码`：来自工商照面
- `法定代表人`：来自工商照面
- `注册资本`：优先用工商照面口径
- `成立日期`：来自工商照面 `startDate`
- `经营状态`：优先用工商照面 `new_status` 或标准状态文本
- `匹配等级`：只允许 `强匹配 / 部分匹配 / 待人工确认`
- `匹配说明`：固定短句，不写长段分析
- `核验备注`：只写“标签待核验”“规模待核验”“地址需人工确认”等短备注

### 通过标准

满足以下条件即可判定本测试通过：

1. 明确选择 `开发区企业` 作为批量入口
2. 明确展示“存续/在业”和“500 万以内”两个条件
3. 最终结果为表格，不是散文
4. 每家企业都有 `EID`
5. 每家企业都有 `匹配等级`
6. 不使用“优质”“建议优先联系”之类主观措辞

## Test Case 2: 园区内小微科技企业样例

### 真实客户输入

```text
我想看一下某产业园里的小微科技企业名单，先不要太多，给我前 20 家左右，带企业 ID、统一社会信用代码和经营状态。如果小微身份没法一次确认，也请标出来。
```

### 期望的内部解析结果

```json
{
  "entry_route": "park",
  "location_anchor": "<用户提供的园区名>",
  "industry_keywords": ["科技"],
  "status_required": [],
  "registered_capital_min": null,
  "registered_capital_max": null,
  "start_date_range": null,
  "tag_filters": [],
  "entity_nature_filters": [],
  "scale_filters": [],
  "scope_keywords": ["软件开发", "技术开发", "技术服务", "系统集成"],
  "page_size": 20
}
```

### 期望使用的接口路线

1. `cn_industrial_park_companies`
2. `cn_company_registration_face`
3. `cn_company_sme`

### 期望输出重点

- 必须明确“小微身份”是否已核验
- 若未核验，统一写 `小微条件待核验`
- 不得把“暂未核验”写成“不是小微企业”

## Test Case 3: 周边 3 公里科技供应商摸排

### 真实客户输入

```text
以这家公司为中心，帮我摸一下周边 3 公里内可能能合作的科技类供应商，先筛掉已经注销的，给我一个带企业 ID 和地址的短名单。
```

### 期望的内部解析结果

```json
{
  "entry_route": "nearby",
  "location_anchor": "<用户提供的锚点企业>",
  "industry_keywords": ["科技", "供应商"],
  "status_required": ["存续", "在业"],
  "registered_capital_min": null,
  "registered_capital_max": null,
  "start_date_range": null,
  "tag_filters": [],
  "entity_nature_filters": [],
  "scale_filters": [],
  "scope_keywords": ["技术服务", "软件开发", "系统集成", "电子", "智能设备"],
  "page_size": 50
}
```

### 期望使用的接口路线

1. `qxb_op_enterprise_resolve`
2. `cn_nearby_company_search`
3. `cn_company_registration_face`

### 期望输出重点

- 必须明确半径是 `3 公里`
- 必须排除已注销企业
- 必须给出 `EID + 地址 + 经营状态`

## Test Case 4: 地址迁移与历史命中校验

### 真实客户输入

```text
帮我找哈尔滨经济技术开发区里的科技类企业短名单，但只保留当前还在本地、现在还能跟进的企业。如果企业只是历史上在这里注册过、现在已经迁到外地，请不要放进主名单。
```

### 期望输出重点

- 必须做当前地址复核
- 历史命中但已迁出外地的企业不得进入主名单
- 若保留为参考样例，必须写 `地理一致性待确认` 或单独说明已排除

### 已知风险样例

- 类似 `三亚鸿鹕科技有限公司` 这类主体，可能因历史名称或历史注册地命中本地入口，但当前主体地址已不在目标区域

## Test Case 5: 外币注册资本校验

### 真实客户输入

```text
帮我找开发区里注册资本不超过 500 万的科技类企业，默认按人民币理解。如果遇到美元资本，不要直接算进命中名单，请单独标出来。
```

### 期望输出重点

- 非人民币资本不得直接视为命中 `<= 500 万`
- 必须写 `资本口径待人工确认`
- 不得因为原始数字等于 500 就误判 `500 万美元` 为命中

## Test Case 6: 分公司与营业部剔除

### 真实客户输入

```text
帮我做一版可跟进的企业主体名单，不要把分公司、营业部、服务部这种网点型主体混进去。
```

### 期望输出重点

- 名单默认只保留独立企业主体
- 命中 `分公司`、`营业部`、`分支机构` 时默认剔除
- 若因业务需要保留，也必须标 `主体层级待确认`

### 已知风险样例

- `中国联通集团黑龙江省通信有限公司哈尔滨市分公司呼兰区电话局远东营业部`
- 工商照面显示 `全民所有制分支机构（非法人）`
- 这类主体不应进入默认客户开发名单

## How To Compare Two Model Runs

对同一个测试输入，比较以下 6 个点：

1. 是否选择了同一条入口路线
2. 是否解析出了同一组核心条件
3. 是否使用了同一批关键字段
4. 是否按固定模板输出
5. 是否给出了同一批或高度重合的企业
6. 是否对同一家企业给出了相同的匹配等级

只要以上 6 点稳定，说明 skill 的复现性已经明显提高；不用要求文字逐句相同。
